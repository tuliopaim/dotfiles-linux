# T3 Code delegation

Only applies inside T3 Code with orchestration tools available.

- Main agent owns implementation, decisions, integration, and final validation.
- Delegate substantial exploration read-only; do small lookups yourself.
  Children return concise findings with file references and never delegate.
- Delegate commits only when requested. Provide the checkout, scope, user
  authorization, and validation results. Tell the child to read and follow
  `~/.agents/skills/commit-work/SKILL.md`. Use Haiku for Claude or Luna for Codex
  for routine commits. Exclude unrelated changes and never push unasked.

| Main agent | Simple child tasks | Complex child tasks |
| --- | --- | --- |
| Codex | `gpt-6-luna` | `gpt-6.1-sol` |
| Claude | `claude-haiku-5-5` | `claude-opus-5-5` |

Use cheaper models only for very simple, bounded tasks such as targeted lookups
or routine commits. Use stronger models for complex exploration, design,
debugging, implementation, and review. Choose supported reasoning or effort
to match the task, not just its category.

- Resolve provider, exact model ID, and supported options with
  `orchestrator_capabilities`; for Claude, also use `t3_thread_configuration`.
  Set them explicitly in `delegate_task`, using effort only when supported.
  Keep children on the same account unless requested otherwise. If the model
  is unavailable, do the work yourself and explain the fallback.
- Give each child a self-contained task with paths, constraints, and expected
  output. Delegate asynchronously, retain task IDs, and review results before
  integrating. Use `task_status` and `task_cancel` as needed.
- Run writers sequentially in a shared checkout. Create separate top-level
  threads only on request.
- Use cross-provider review when requested. Use the specified Claude account,
  or ask which account when unclear.
